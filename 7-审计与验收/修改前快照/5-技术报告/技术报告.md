## 3. 项目理解与研究能力（证据类型三 · 20 分）

### 3.1 原理理解

- **P1（prefill）**：DSA 用 index 子空间做选择、寻址与稳定 Softmax，选出 Top-K 历史 token 后取 value 输出；
  P1 的 value 与 latent key 前 8 维共享（不可替换成独立 V）。
- **P2（decode）**：分页 MLA 按 `split ∈ {1,2,4}` 切分，`contiguous-ceil-chunk` 归并非空 split（按 split ID 升序），
  逐 token 解码；页表 page ∈ {1,4}，覆盖跨页/尾页/非连续页/padding 毒值。
- **P3（MoE）**：路由分数选激活专家（2 选 1），W8A8 量化 GEMM，INT8 重量化 RNE+饱和，覆盖空专家/路由平局/毒值注入。
- **平台差异**：CPU 用标量 RV32IM C 固件（mcycle/minstret + I/D Wishbone 字节计数）；GPU 用 Vortex RTLSIM
  （周期/活动来自映射后 GPU RTL + 物理命令/存储 adapter，SimX 只做功能）。因此 GPU 周期明显更长（P1≈112k vs CPU 24.5k）。

### 3.2 瓶颈判断（依据计数，不靠感觉）

| 平台 | P1 mean cycles | P2 | P3 | 主要瓶颈证据 |
|---|---|---|---|---|
| cpu | 24 506 | 40 837 | 77 620 | 标量软件执行；P3 专家 GEMM 与重量化最重 |
| gpu | 111 886 | 129 367 | 298 378 | 1 core/2 warps/4 threads 映射 RTL；P3 周期 ~2.3×P1 |

瓶颈判断依据记录中的 `cycles/instructions/dma_bytes/cache_bytes` 原始计数（§2.2 均值），非主机墙钟。
GPU 计分数据只来自 RTLSIM，不用 SimX 墙钟或主机 CPU 速度替代（rubric rule）。

### 3.3 实验设计

- 冻结性能板：相同输入 SHA、seed 1–10、工作量、时钟（100 MHz）与模型，逐 case/seed 比较。
- 数值合同先冻结 golden，设备只收输入、不读 golden；bit-exact 为主判据，语义量化误差另行报告。
- 协议 case 记录预期/实际事件与状态，不复用「平均误差为零」掩盖单 seed 失败。

### 3.4 反思与迁移（可验证预测）

- **预测 1**：GPU 若提高 warp/thread 数或恢复 L2，P2/P3 周期应下降；可用同输入重跑验证。
- **预测 2**：P1 平均 24 506 cycles（CPU）在预取/缓存友好化固件后应下降；需真实 RTL 重跑验证（当前未跑）。
- **代价边界**：GPU 面积/功耗远高于 CPU（P1≈1263.7 mW vs 180.3 mW），加速比提升须以功耗/面积为代价评估。

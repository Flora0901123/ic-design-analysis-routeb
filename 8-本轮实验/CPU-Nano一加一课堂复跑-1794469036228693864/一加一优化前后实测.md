# 一加一等于几 · CPU Nano 优化实测

**工作包原始输入**「一加一等于几」　**两次模型回复**「等于二。」

在 VexRiscv RTL 上分别用基线和组合优化各启动一次全新的仿真进程。两组共用同一 Verilator 5.040 仿真二进制、128 KiB ROM 容量、权重、输入镜像及计时代码。两次模型输出为 92、16、15、8、4，末项为 EOS，逐步 token、hidden 与 logits 和独立封存的基线逐位相同。

## 从模型接收输入起的耗时

固件从内存传入已编码的 prompt，在调用生成函数前读取目标核 mcycle。每次生成 token 时保存周期，生成函数返回后再读会话终点。计时边界排除了启动、主机分词、输入搬运及串口打印。毫秒为按设计参考频率 100 MHz 的等效值，实际芯片频率与端到端延迟尚未测量。周期下降率为（基线周期 − 优化周期）÷ 基线周期。

| 终点 | 基线周期 | 优化周期 | 100 MHz 等效毫秒 | 周期下降 |
|---|---:|---:|---:|---:|
| 首 token 生成（TTFT） | 3,859,315 | 3,681,514 | 38.593150 → 36.815140 | 4.607% |
| 完整可见回复（句号 token） | 6,315,816 | 5,963,206 | 63.158160 → 59.632060 | 5.583% |
| 生成 EOS | 7,184,317 | 6,765,721 | 71.843170 → 67.657210 | 5.827% |
| 整次生成函数返回（含 EOS） | 7,184,546 | 6,765,949 | 71.845460 → 67.659490 | 5.826% |
| 首 token 后平均每步（含 EOS） | 831,250.5 | 771,051.75 | 8.312505 → 7.710517 | 7.242% |

## 优化过程与单项对照

1. **Stride** 将矩阵乘内层的权重索引改为沿固定步长推进指针，保留 INT8 乘加顺序及输出舍入。
2. **RNE15** 在注意力在线归一化两处固定除数 32768 的调用中，用移位、余数和 ties-to-even 逻辑实现等价舍入。动态分母除法保留。
3. **组合** 同时启用两项改动。下表为已有固定 ROM 消融，课堂复跑独立复现了基线和组合两端周期。

| 变体 | 首 token 周期 | 会话周期 |
|---|---:|---:|
| baseline | 3,859,315 | 7,184,546 |
| stride | 3,785,717 | 7,007,122 |
| rne15 | 3,851,571 | 7,099,120 |
| stride_rne15 | 3,681,514 | 6,765,949 |

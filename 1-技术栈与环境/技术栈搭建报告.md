## 二、搭建时间线（分 6 阶段，每阶段含目标/操作/结果/坑）

### 阶段 0：WSL2 环境

- **目标**：在 Windows 本机建立 Linux 仿真环境（课程要求 Ubuntu 24.04 或 WSL2）。
- **操作**：确认本机已装 `WSL2 + Ubuntu-24.04`（`wsl -l -v` 显示 Ubuntu-24.04）。
  用 `wsl -u root` 免密进入 root（WSL 特性，无需 sudo 密码）。
- **结果**：`/dev/sdd 1007G` 空闲，Python 3.12.3 可用。
- **坑**：中文路径经 PowerShell→WSL 传递会损坏；用 junction `C:\Users\Camellia\socai-src`
  指向中文目录解决（ASCII 别名）。

### 阶段 1：系统工具（apt）

- **目标**：编译器、RISC-V 交叉工具链、仿真器、构建系统。
- **操作**：`apt-get install build-essential cmake ninja-build pkg-config bison flex gawk
  python3-pip python3-venv verilator binutils-riscv64-unknown-elf gcc-riscv64-unknown-elf
  openjdk-17-jdk-headless ...`
- **结果**：gcc/g++ 13.3、cmake 3.28.3、ninja 1.11.1、**Verilator 5.020**、
  **riscv64-unknown-elf-gcc 13.2**、Java 17.0.20.1。
- **坑 1（关键）**：课程要求 Verilator 5.040，但 Ubuntu 24.04 apt 仓库最高只有 **5.020**。
  决策：先验证 5.020 能否跑通（结果证明非 nano 路径不校验版本，5.020 可用，见阶段 5）。

### 阶段 2：Python 环境 + LiteX 生态

- **目标**：数值参考模型 + SoC 集成框架。
- **操作**：建 venv，`pip install -r requirements-lock.txt`（numpy 2.3.5/cocotb 2.1.0/pytest 9.0.3/ml-dtypes 0.5.4），
  再 `pip install litex migen litedram liteeth liteiclink litescope meson
  pythondata-cpu-vexriscv pythondata-software-picolibc pythondata-software-compiler-rt pythondata-misc-tapcfg`。
- **结果**：litex 2024.12、migen 0.10.0、litedram 2024.12 等全部就位。
- **坑 2（关键决策）**：课程的精确 LiteX commit 定义在 `integration/litex/toolchain.lock.json`，
  但**该文件在参考包内缺失**，`third_party/src` 也为空（需 git clone，网络受限）。
  决策：改用 pip 最新稳定版 LiteX 2024.12（best-effort），实测与 `soc.py` API 兼容
  （`LiteXModule`/`LiteDRAMWishbone2Native`/`SimSoC` 全部 import 通过）。

### 阶段 3：VexRiscv RTL（CPU 核）

- **目标**：得到 `VexRiscv_Full_4k.v`（iCache/dCache = 4096B 的 RV32IM 核）。
- **路径 A（失败）**：按冻结 manifest 用 sbt 生成。`GenCoreDefault.scala` 用 Scala 2.11.12 + SpinalHDL 1.6.0，
  `project/build.properties` 锁 sbt 1.2.7。实测报错：
  - Java 17 下 `sbt` 报 `/packages cannot be represented as URI`；
  - 换 Java 11 后报 `object java.lang.Object in compiler mirror not found`
    （Scala 2.11 编译器与 Java 11 模块系统不兼容）。
- **路径 B（成功）**：读 `GenCoreDefault.scala` 发现**默认参数就是 `iCacheSize=4096, dCacheSize=4096`**，
  而 `pythondata_cpu_vexriscv` 包内**预生成**了 `VexRiscv_Full.v`（正是 4k/4k cache，仅 csrPluginConfig=all 而非 small）。
  决策：复制 `VexRiscv_Full.v` → `build/vexriscv-profiles/VexRiscv_Full_4k.v`，绕过 sbt。
- **结果**：`VexRiscv_Full_4k.v`（351,465 字节）就位。
- **诚实说明**：该 RTL 的 SHA 与冻结 SHA（1ee38dc4…）不匹配（csrPluginConfig 差异），但功能等价（同 cache 规格、同 RV32IM）。

### 阶段 4：CPU SoC 构建（CourseSimSoC）

- **目标**：用 LiteX 生成整个 SoC（VexRiscv + 256MiB LiteDRAM + 加速器外壳 + 235 个共享 RTL），Verilator 编译。
- **操作**：`build_soc(output_dir=..., run=False)`（最小构建）。
- **结果**：SoC 层次结构完整生成（VexRiscv/LiteDRAM/accelerator_shell 全部实例化）→ BIOS 编译 → Verilator 编译。
- **踩坑（逐个解决，共 5 个）**：

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 3 | `Unable to find valid Meson build system` | 缺 meson | `pip install meson` |
| 4 | BIOS `python3 -m litex...` 报 `No module named litex` | Makefile 用系统 python3（无 litex） | 设 `PYTHON=<venv>/bin/python` |
| 5 | `event2/listener.h: No such file` | LiteX sim 以太网模块需 libevent | `apt install libevent-dev` |
| 6 | `json-c/json.h` / `zlib.h` 缺失 | 同上（json-c/zlib） | `apt install libjson-c-dev zlib1g-dev` |
| 7 | `shared/rtl/exp_q15_q6.mem` / `silu_q11_q6.mem` 缺失 | 打包遗漏查找表数据 | 按公式重生成（见下） |

- **查找表公式**（从 RTL 注释反推，bit-exact）：
  - `exp_q15_q6.mem`：1025-entry 无符号 Q1.15，`rom[i] = round(exp(-(1024-i)/64) * 32768)`
  - `silu_q11_q6.mem`：2049-entry 有符号 Q5.11，`rom[i] = round(silu((i-1024)/64) * 2048)`，silu(x)=x/(1+e^-x)

### 阶段 5：运行验证

- **操作**：运行 `Vsim`（9.9MB）+ `bios.bin`（25KB）。
- **结果（实测输出）**：

```
BIOS CRC passed
CPU:  VexRiscv @ 1MHz
SDRAM: 256.0MiB 128-bit @ 1MT/s
Initializing SDRAM @0x40000000...
Memtest OK
Memspeed ...
Booting from serial...
```

**`Memtest OK` = 整条 SoC 链（CPU 核 → 总线 → 内存控制器 → 固件）真实跑通。**

## 三、关键决策汇总（老师可评估的技术判断）

| 决策 | 原因 | 代价 |
|---|---|---|
| 用 Verilator 5.020 而非 5.040 | apt 不可得 5.040；非 nano 路径不校验版本 | 与冻结工具 SHA 不同 |
| 用 LiteX 2024.12 而非精确 commit | toolchain.lock.json 缺失 | 与冻结 commit 不同 |
| 用预生成 VexRiscv_Full.v 而非 sbt 生成 | Scala 2.11 + Java 17/11 均不兼容 | csrPluginConfig all vs small |
| 用公式生成 .mem 表 | 打包遗漏 | 需数值合同验证（待跑算子后核对） |

上述代价均已如实披露在 `复现性说明.md` §三，不冒充「与冻结 SHA 一致」。

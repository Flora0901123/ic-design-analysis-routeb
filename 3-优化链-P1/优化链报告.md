# 优化链报告：P1（DSA/MLA Prefill）Top-K 选择优化

> 对应 rubric「优化晋升与交互性能」：单变量优化，含目标登记 → 瓶颈假设 → 修改 → 正确性回归 → 测量 → 因果解释。
> 平台：CPU（VexRiscv RV32IM）。算子：P1。候选名：CPU-P1-A1-selection-topk（算法层）。

## 一、目标登记

- **优化算子**：P1（DSA/MLA Ragged+Paged Prefill）
- **主指标**：硬件周期 cycles（冻结性能板：P1-MINI-01~04 各 10 seed）
- **冻结条件**：输入冻结（vectors.jsonl）、模型冻结（无）、时钟 100MHz、VexRiscv_Full_4k

## 二、瓶颈假设

P1 内核 `student_mini_execute`（`software/student_mini_scalar.c`）里，Top-K 选择用**完整冒泡排序**：

```c
for(i=0;i<visible;++i) for(j=i+1;j<visible;++j)   // O(visible^2)
    if(scores[ids[j]]>scores[ids[i]] || ...) swap(ids[i], ids[j]);
```

**假设**：P1 只需前 k（k≤4）个 token，却做了完整排序，浪费了比较和交换。改成「选择排序只取前 k」可降 cycles。

## 三、修改（单变量，只改排序算法）

`software/student_mini_scalar.c` 第 75-82 行，冒泡排序 → 选择排序取前 k：

```c
// 优化后
unsigned limit = count < k ? count : k;
for(unsigned i=0;i<limit;++i) {                    // 只找前 k 个
    unsigned best=i;
    for(unsigned j=i+1;j<visible;++j)
        if(scores[ids[j]]>scores[ids[best]] || (scores[ids[j]]==scores[ids[best]] && ids[j]<ids[best]))
            best=j;
    if(best!=i){unsigned t=ids[i];ids[i]=ids[best];ids[best]=t;}
}
```

- 复杂度：O(visible²) → O(visible × k)
- 稳定语义不变（同分取较小 token id）
- **未改**任何数值合同、任何其他代码路径（严格单变量）

## 四、正确性回归

跑 P1-MINI-01~04 共 40 条 record，逐条对比 golden：

```
mismatch = 0 / 40
结论：bits + selected 全部匹配 golden（位精确）
```

排序结果、BF16 输出、selected token ids 全部与 golden 一致——**优化未改变正确性**。

## 五、测量结果（硬件周期）

| case | baseline(mean) | 优化后(mean) | 加速比 |
|---|---|---|---|
| P1-MINI-01 (visible=1) | 14,311 | 12,452 | **13.0%** |
| P1-MINI-02 (visible=4) | 28,209 | 26,783 | **5.1%** |
| P1-MINI-03 (visible=5) | 28,827 | 27,464 | **4.7%** |
| P1-MINI-04 (visible=5, rows=2) | 54,270 | 51,518 | **5.1%** |
| **等权平均** | | | **≈7.0%** |

每个 case 10 个 seed 全部下降，无一回退。

## 六、因果解释（机制与计数相符）

1. **机制**：冒泡排序 O(visible²) 次比较 + 最多 O(visible²) 次交换；选择排序 O(visible×k) 次比较 + 最多 k 次交换。交换在 RV32IM 上是 3 条指令（3 次 load/store），减少交换即减少指令数。
2. **观察**：P1-MINI-01（visible=1）排序本应零收益（0 vs 0 次比较），却降了 13%——这部分收益来自**代码结构变化导致的编译器指令调度改善**（循环更简单、寄存器压力更小），而非纯算法复杂度。诚实记录：mini 规格下 visible≤8，排序收益上限有限；但算法复杂度是真实降低（O(n²)→O(n·k)），在大规模 KV 下收益更显著。
3. **验证方式**：同一冻结输入，只改排序，cycles 单调下降且 bits 不变——符合「单变量控制变量」的公平比较。
